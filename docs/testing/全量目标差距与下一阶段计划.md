# 全量目标差距与下一阶段计划

## 当前结论

最终目标尚未达成，不能认定为完整验收。

当前已完成的是“预约闭环 MVP”的部分后端规则和一批基础前端页面接入；这只能证明最小链路可以跑通，不代表产品体验、商家后台、活动、助教、客户沉淀和全量数据口径已经完成。

## 已阶段通过

- 后端预约闭环：创建预约、提交到店、确认到店、开台、关台、爽约限制、解除限制。
- 后端本地测试：`15/15` 通过。
- 前端基础链路：预约页、我的预约、员工工作台、到店核实页已接入真实 action。
- 首页验收区已移除，不再暴露调试入口。
- 第一轮 UI 设计已开始落地：全局视觉系统、首页、预约页、我的预约、员工工作台、到店核实、价格页、桌台网格、商家后台首页。

## 未完成项

### 产品与验收

- 尚未按 PRD 做全量验收。
- 真实门店资料、真实价格、真实桌台编号、真实助教资料未替换。
- 目前验收口径仍偏 MVP，不是完整试运营口径。

### 前端 UI

- 已完成第一轮视觉系统，但还未覆盖所有页面的精修。
- 活动列表、活动详情、活动报名、助教列表、助教预约、商家配置、爽约限制页仍需继续设计和交互完善。
- 预约页还缺日期选择、时间选择器、备注输入、预计价格、可用性提示。
- 我的预约还缺状态筛选、详情页、不同状态的差异化按钮。

### 后端

- 预约闭环已做，但不等于后端完整。
- 商家配置接口未完整实现：门店、桌台、价格、助教、活动配置。
- 活动报名只有基础创建，缺手机号授权、限额并发、报名名单、审核。
- 助教预约缺员工确认、助教状态切换、助教状态流水。
- 客户沉淀缺客户列表、用户档案、手机号授权、标签。
- 桌台管理缺手动切换维修/停用/清洁状态接口。
- 当前仍保留 `bootstrapMvp`、烟测 action 等测试辅助接口，后续应与生产能力隔离。

### 测试

- 已有后端单测，但缺前端手工验收记录。
- 缺多账号真实验收：普通用户、员工、店长分开测试。
- 缺完整 40 桌数据口径验收。
- 缺活动、助教、商家配置、客户沉淀的验收用例。
