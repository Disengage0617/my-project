## 当前结论

后端已不再只是预约闭环 MVP：代码中已经存在商家配置、活动报名名单、助教确认、客户列表、桌台状态、审计日志、Web 后台接缝等基础 action，并且本地测试 `25/25` 通过。

但这些 action 多数仍是“基础可用/本地测试级”，未达到真源要求的完整生产级能力。主要缺口集中在：活动限额并发与审核动作、手机号授权真实链路、商家配置字段级校验与安全约束、助教预约完整状态机/流水、客户标签与资料沉淀、配置类写操作的防越权/防误停用细则、分页和查询条件、真实云端联调。

## 已覆盖接口

### 门店、价格、页面与素材

- `getStoreOverview`：首页概览，读取门店、桌台、助教、活动。
- `getStoreDetail`：门店详情。
- `getPriceRules`：价格规则读取。
- `getPageConfig` / `managePageConfig`：页面配置读取、保存/发布，写 `audit_log`。
- `getAssets` / `manageAssets`：素材库查询、软删除/新增/更新，写 `audit_log`。

### 商家配置

- `manageStore`：门店配置 upsert/update，manager 权限，写 `audit_log`。
- `manageTables`：桌台 list/upsert/disable，manager 权限，写 `audit_log`。
- `managePriceRules`：价格规则 list/upsert/disable，manager 权限，写 `audit_log`。
- `manageAssistants`：助教资料 upsert/disable，manager 权限，写 `audit_log`。
- `manageCampaigns`：活动 upsert/publish/offline，manager 权限，写 `audit_log`。

### 预约闭环与桌台状态

- `getAvailableTables`、`createReservation`、`getMyReservations`、`getReservationDetail`。
- `submitArrival`、`confirmArrival`、`rejectArrival`、`markNoShow`、`openTable`、`closeTable`、`releaseReservation`。
- `getStaffWorkbench` / `getTodayReservations` / `getAdminReservations`。
- `updateTableStatus`：支持 `idle`、`cleaning`、`repairing`、`disabled`，写 `table_status_log`。
- `getNoShowRecords`、`liftNoShowBan`，解除限制写 `audit_log`。

### 助教

- `getAssistants`、`getAssistantDetail`。
- `createAssistantReservation`：创建助教预约，校验助教状态和时间冲突。
- `confirmAssistantReservation`：员工确认，确认前二次冲突校验。
- `updateAssistantStatus`：切换助教状态，写 `assistant_status_log` 和 `audit_log`。

### 活动与客户沉淀

- `getCampaigns`、`getCampaignDetail`。
- `createCampaignRegistration`：校验活动发布、昵称/手机号、重复报名、名额基础判断，按 `need_review` 设置 `pending_review` 或 `approved`。
- `getCampaignRegistrations`：报名名单，staff 手机号脱敏，manager/admin 查看完整手机号。
- `getMineCenter`：我的页资料、授权状态、余额/券/订单/预约/助教预约/活动报名/爽约限制只读汇总。
- `getCustomers`、`getCustomerProfile`：客户列表与档案，手机号按角色脱敏。
- `getAuditLogs`：审计日志查询。

### 测试/初始化辅助

- `bootstrapMvp`、`validateMvpBootstrap`、`runMvpFlowSmokeTest`、`runMvpGuardSmokeTest` 仍存在，已标记为测试辅助能力，不应作为正式生产入口暴露给普通路径。

## 缺失接口与能力缺口

### P0 缺口

- 活动审核缺少明确 action：建议补 `reviewCampaignRegistration`，支持 `approve` / `reject`，记录 `reviewed_by`、`reviewed_at`、`reject_reason`、`audit_log`。
- 活动限额并发未达真源要求：当前 `createCampaignRegistration` 使用读取 `quota_used` 后更新的方式，缺事务或 `reservation_lock` 风格短锁，存在并发超报风险。
- 手机号授权真实链路缺口：`authorizePhone`、`loginByWechat`、`getCurrentRole` 在 docs 中有协议，但当前 handler 未导出；活动报名可从 `payload.profile.phone` 兜底，不能替代真实微信手机号授权。
- `manageTables` 的 `disable` 路径缺少和 `updateTableStatus` 一样的有效预约保护，可能绕过“有有效预约不得停用桌台”的规则。
- 配置类 upsert 缺字段级校验：`manageStore`、`manageTables`、`managePriceRules`、`manageAssistants`、`manageCampaigns` 对状态枚举、金额、时间、必填、长度、业务范围校验不足。
- 活动报名、客户、审计、预约后台列表缺分页限制：文档要求 `page/page_size`，当前多数直接 `.get()` 全量返回。

### P1 缺口

- 助教预约状态机不完整：已有创建和确认，但缺 `startAssistantService`、`completeAssistantService`、`cancelAssistantReservation`、`markAssistantNoShow` 或统一 `updateAssistantReservationStatus`。
- 助教预约流水缺口：`updateAssistantStatus` 有 `assistant_status_log`，但助教预约确认/开始/完成/取消没有独立预约状态流水或审计日志。
- 活动报名取消/重复报名释放名额缺口：已有重复报名拦截，但缺用户取消、后台取消、审核拒绝后名额回滚的统一规则。
- 客户沉淀仍偏统计读取：缺 `updateCustomerTags`、`updateCustomerRemark`、客户来源/偏好更新、手机号授权后回填 `customer_profile` 的明确 action。
- 审计日志覆盖不均：配置和关键员工动作有审计，创建预约、助教预约创建/确认、活动报名创建暂未形成完整审计口径。
- 桌台维护状态细则不足：`updateTableStatus` 能切 `cleaning/repairing/disabled`，但缺“清洁完成”语义 action、缺维修原因必填、缺停用时未来预约处理策略。

### P2 缺口

- `getAvailableTables` 当前主要返回启用桌台列表，未按传入时间排除已有预约冲突并标记 `available=false`。
- `getAdminDashboard` 指标为基础聚合，未按日期范围/今日口径/待审核活动报名等细分。
- `getCampaigns` / `getAssistants` / `getCustomers` 缺排序、筛选、分页、关键字统一协议。
- docs/backend/api.md 仍保留旧版 `{ success, error }` 响应示例，而入口实际返回 `{ ok: true, data }` / `{ ok:false, code, message }`，需要统一真源协议。
- 测试辅助 action 需要生产隔离策略：例如仅本地/显式管理员可调，或部署前从公开 action 表移除。

## 数据模型缺口

- `campaign_registration` 缺审核拒绝原因、取消原因、名额回滚记录、状态变更流水。
- `assistant_reservation` 缺状态流水集合或统一审计字段，无法完整追踪确认、开始、完成、取消、爽约。
- `customer_profile` 缺标签/备注更新 action；手机号授权后写入 `user` 与 `customer_profile` 的链路未落地。
- `reservation_lock` 已用于桌台预约锁，但活动名额和助教单独预约尚未使用统一短锁/事务策略。
- 配置类集合缺唯一性/约束兜底说明的代码级实现证据，例如 `store_id + table_no`、`campaign_id + user_id`。

## 权限与状态机缺口

- manager/staff 权限基础存在，但配置类字段级授权不足，例如价格、活动名额、停用桌台都走通用 manager upsert。
- `manageTables:disable` 与 `updateTableStatus:disabled` 规则不一致。
- 活动报名审核状态机缺失，无法从 `pending_review` 合法流转到 `approved/rejected`。
- 助教预约状态机缺开始服务、完成服务、取消、未到店流转。
- `updateAssistantStatus` 只禁止 `serving -> checked_out`，其他非法流转细则较少。
