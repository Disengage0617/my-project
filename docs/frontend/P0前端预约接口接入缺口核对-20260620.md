## 核对结论

小程序 P0 用户预约体验的前端主链路已覆盖：首页进入预约、预约页查询可用桌台和助教、创建预约、我的预约列表筛选与到店提交、预约详情查询与到店提交。

本轮发现并补齐 3 类普通前端缺口：

- 首页桌区入口只跳转预约页，未把 A-E 桌型带入预约页。
- 预约详情页只有详情展示，没有 `submitArrival` 的详情页入口、提交中状态和成功后刷新。
- mock/API 兼容层缺少后端新增的 `INVALID_TIME`、`INVALID_TIME_RANGE` 错误文案，`getAvailableTables/getAssistants` 返回结构和 `submitArrival` 的 snake_case 兼容可加强。

未做 UI 风格重做，未修改后端、Web 后台、真实数据库或部署配置。

## 完成内容

- 首页 `selectZone` 写入 `globalData.pendingReservationTableType`，预约页 `onShow` 消费该桌型并刷新 `getAvailableTables`，保证从首页点击独牙/金腿等分区可直接进入对应筛选。
- 预约页保持 `selectedDate + startTime + durationHours` 统一生成 `startTime/start_time/endTime/end_time`，继续兼容 `getAvailableTables` 的 `list/items/tables` 返回。
- 预约详情页补 `submitArrival` 入口：待到店状态显示“我已到店”，提交时防重复，成功后刷新详情。
- API mock 兼容后端错误码：新增 `INVALID_TIME`、`INVALID_TIME_RANGE` 文案。
- API mock 返回增强：`getAvailableTables` 返回 `list/items/tables/total`；`getAssistants` 返回 `list/items/total`；`submitArrival/confirmArrival/markNoShow/openTable/closeTable` 兼容 `reservationId/reservation_id`。
