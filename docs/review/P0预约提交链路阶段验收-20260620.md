## 3. 验收结论

结论：本地 mock/静态层 P0 预约提交链路可以阶段收口。

验收官判断依据：

- 后端基线已包含 `createReservation/getReservationDetail/getMyReservations/submitArrival` 等预约链路 action，本地后端测试 29/29 通过。
- 前端已补齐首页桌型进入预约、预约页创建预约 payload、预约详情“我已到店”、我的预约/详情刷新和 API/mock 字段兼容。
- QA 初测发现 P0 阻塞：mock `createReservation` 未写回状态，导致新预约无法在详情和我的预约中读取。
- 前端已修复 mock 状态闭环。
- QA 复测确认 mock chain 通过：新预约可查详情、可出现在我的预约，`submitArrival` 后详情和列表均刷新为 `pending_verify`。

因此，本地 mock/静态层的“创建预约 -> 查询详情 -> 我的预约出现新预约 -> 我已到店 -> 状态刷新为待核实”链路通过。

但该结论不能写成微信开发者工具真实页面通过，也不能写成真实云端预约写入通过。

## 4. 已通过范围

- 后端 action 基线和本地测试：
  - `createReservation`
  - `getReservationDetail`
  - `getMyReservations`
  - `submitArrival`
  - 后端 `npm test` 29/29 通过。
- 前端静态接缝：
  - 预约页 payload 同时兼容 camelCase/snake_case。
  - 首页桌型可带入预约页。
  - 预约详情页已有“我已到店”入口、防重复和提交后刷新。
  - 我的预约和预约详情使用同一状态字段刷新。
- mock 状态闭环：
  - `createReservation` 写回 `mock.reservations`。
  - `getReservationDetail(createdId)` 可读取新预约。
  - `getMyReservations` 包含新预约。
  - `submitArrival(createdId)` 后详情和列表状态刷新为 `pending_verify`。
- QA 复测关键输出：

```json
{
  "duyaCount": 8,
  "createdInDetail": true,
  "createdInMyReservations": true,
  "arrivalStatus": "pending_verify",
  "detailStatusAfter": "pending_verify",
  "listStatusRefreshed": true,
  "ok": true
}
```
