## 3. 主要缺口

### P0 缺口

1. 预约页还缺日期选择。
   - 当前只有当天/次日自动推算的 `startTime`，没有显式日期控件。
   - `getAvailableTables` 调用未带 `startTime/endTime/tableType`，桌台列表不是按所选时段动态可用性刷新。

2. 预约页预计价格和可用性提示不足。
   - 页面展示桌台单价，但未计算 `durationHours * tablePrice + assistantPrice` 的预计价格。
   - 未区分 `available=false`、已预约、使用中、维修/停用等不可选状态；选择不可用桌台仍可能进入提交，主要依赖后端拦截。

3. 我的预约缺筛选与详情按钮。
   - 未实现“全部 / 待到店 / 待核实 / 进行中 / 历史”等 tabs。
   - 列表没有“查看详情”入口，无法进入 `reservation-detail` 查看完整预约信息。
   - 状态文案里 `pending_arrival` 当前显示为“未到店”，应与状态机统一为“待到店”。

4. 小程序与后端字段格式仍需收敛。
   - 小程序常传 `storeId/startTime/endTime`，接口文档同时存在 `store_id/start_time/end_time` 口径；服务端目前做了兼容，但前端应逐步统一在 service 层转换，页面不要分散兼容。
   - `getAvailableTables` 后端文档返回 `tables/items` 口径，小程序当前主要取 `res.list`，需要补 `tables/items` 兼容。

### P1 缺口

1. 活动详情字段兼容不足。
   - 后端真实字段是 `quota_total/quota_used/content/rules/need_review/member_only`，当前详情页主要读 `quota/registeredCount/rule`。
   - 报名成功后未跳转“我的活动报名”或刷新报名状态。

2. 助教预约缺完整时段和备注。
   - 预约页只有默认开始时间和时长调整，缺日期/时间选择、备注输入、价格估算、可预约状态提示。
   - `createAssistantReservation` 后端支持 `remark/reservation_id`，当前单独预约未传 remark。

3. 商家配置入口只读多、编辑少。
   - 小程序 `merchant-config` 主要是联调/配置状态检查，完整编辑保存链路在 Web 后台。
   - 若要小程序内商家配置，需要补门店/桌台/价格/活动编辑表单；若保留 Web 后台为主，小程序端应弱化为入口和状态摘要。

4. 爽约限制页缺权限与解除原因输入。
   - `liftNoShowBan` 后端要求 manager/admin 和 reason；当前页面传固定 reason，没有输入框和权限状态。

### P2 缺口

1. 客户/订单/优惠券/储值仍是只读展示，符合一期边界，但缺真实云端验收。
2. Web 后台配置保存链路仍是本地 mock 证据，未证明真实云函数/数据库保存。
3. 小程序活动报名手机号授权真实换号能力未接，只能拿到 code 或手动填写手机号。
4. `submiting` 字段拼写不统一，建议后续顺手改为 `submitting`，但不影响当前运行。

## 5. 建议实施顺序

### P0：先补预约和我的预约

1. 预约页补日期选择、统一 `selectedDate + startTime + durationHours` 生成 `startAt/endAt`。
2. `getAvailableTables` 随日期/时间/时长变化刷新，兼容 `list/items/tables`。
3. 桌台卡补可用性状态，不可用桌台禁选，并展示下一可约时间/冲突提示。
4. 补预计价格：桌台价、助教价、时长合计；提交前展示确认摘要。
5. 我的预约补状态筛选 tabs、详情入口、状态文案统一和差异化按钮。

### P1：补活动、助教、爽约限制

1. 活动详情兼容真实字段，报名后跳转/刷新到“我的活动报名”。
2. 助教预约补日期/时间、备注、预计价格和可约状态提示。
3. 爽约限制解除补原因输入、权限提示和解除后刷新。
4. 小程序商家配置明确定位：如果以 Web 后台为主，小程序端只保留状态摘要和跳转说明；如果要小程序内配置，再拆单独表单实现。

### P2：补后台真实接入与只读体验完善

1. Web 后台从 mock 切真实云函数接缝，保留 `web-admin/src/api.js` 作为唯一替换点。
2. 客户、订单、优惠券、储值继续只读，但补空态、字段脱敏和真实云端验收。
3. 活动报名手机号授权由后端补 `authorizePhone` 或换号能力后再接入。
