## 当前静态基线

### 首页助教卡

- `miniprogram/pages/home/index.wxml` 中助理教练卡为 `.coach-entry`，存在 `bindtap="goAssistants"`。
- `miniprogram/pages/home/index.js` 中 `goAssistants()` 当前调用 `wx.navigateTo({ url: "/pages/assistant-list/index" })`。
- `miniprogram/app.json` 中 `pages/assistant-list/index` 是底部 Tab 页面，按小程序规则从非 tab 页面进入 tab 页面通常应使用 `wx.switchTab`。
- 因此用户反馈“点击不跳转”的高概率根因是跳转 API 类型不匹配。

### 预约时间滚轮

- `miniprogram/pages/reservation/index.wxml` 使用双列 `picker-view`：
  - 第一列：`timePickerHours`
  - 第二列：`timePickerMinutes`
  - 绑定值：`value="{{timePickerValue}}"`
  - 变更事件：`bindchange="changeTimePicker"`
- `miniprogram/pages/reservation/index.js` 当前分钟数组为 12 个 5 分钟粒度值：`00/05/10/.../55`。
- `changeTimePicker(e)` 当前同步更新：
  - `timePickerValue`
  - `startTime`
- `submitReservation()` 当前通过 `buildStartAt(this.data.startTime)` 生成提交 payload 的 `startTime`。

### TC-RES-TIME-001：选择 04:00 后不回弹

复现步骤：

1. 进入预约页。
2. 滑动小时列到 `04`，分钟列到 `00`。
3. 等待 1 秒。
4. 观察顶部“预计 04:00 到店”和滚轮高亮位置。
5. 上下轻滑页面或点击桌台卡，再回看时间。

期望结果：

- 顶部展示保持 `04:00`。
- 滚轮位置保持 `04` / `00`。
- 不回弹到 `00:00`、默认时间或其他值。

失败判定：

- 顶部展示变为 `00:00`。
- 滚轮高亮回到 `00` 小时。
- 点击其他控件后时间被重置。

### TC-RES-TIME-002：任意 5 分钟粒度值保持

测试数据：

- `04:05`
- `09:35`
- `18:55`
- `23:50`

复现步骤：

1. 对每个测试数据滑动选择对应小时和分钟。
2. 每次选择后等待 1 秒。
3. 观察顶部展示与滚轮位置。

期望结果：

- 顶部展示值与滚轮选择值完全一致。
- 分钟列只能落在 `00/05/10/.../55`。
- 不出现非 5 分钟粒度。

失败判定：

- 分钟值变成 `00` 或默认值。
- 顶部展示和滚轮位置不一致。
- 分钟列可落在非 5 分钟值。

### TC-RES-TIME-003：提交 payload 与 UI 选择一致

复现步骤：

1. 选择 `04:00`。
2. 选择一张桌台。
3. 点击提交预约。
4. 在开发者工具 Network/console 或 mock spy 中检查调用 `createReservation` 的 payload。

期望结果：

- payload 中 `startTime` 对应本地日期的 `04:00:00`。
- payload 中 `endTime` = `startTime + durationHours`。
- 顶部展示、滚轮位置、payload `startTime` 三者一致。

失败判定：

- UI 显示 `04:00`，payload 却为 `00:00` 或默认时间。
- `endTime` 与选择时长不一致。

### TC-RES-TIME-004：切换时长/桌台/助教不重置时间

复现步骤：

1. 选择 `09:35`。
2. 调整时长 `+/-`。
3. 切换桌台。
4. 选择或取消助教。
5. 观察顶部展示与滚轮位置。

期望结果：

- `startTime` 始终保持 `09:35`。
- 仅时长变化影响 `endTime`，不影响预计到店时间。

失败判定：

- 任意操作导致时间回弹到默认值或 `00`。

### TC-RES-TIME-005：页面生命周期不异常重置

复现步骤：

1. 选择 `18:55`。
2. 从预约页切到首页，再切回预约页。
3. 如前端预期保留用户选择，则检查是否仍为 `18:55`；如预期重新初始化，则检查是否按默认时间初始化且不显示 `00:00`。

期望结果：

- 行为符合前端交付说明。
- 不允许异常显示 `00:00`。

失败判定：

- 切回页面后变成 `00:00`。
- 顶部展示、滚轮位置不一致。
