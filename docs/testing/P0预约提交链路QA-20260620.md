## 失败项

### F-01 mock action 不支持创建预约后的详情/列表刷新

严重等级：P0-blocker（阻塞本地 mock 层预约提交闭环 QA）。

复现步骤：

1. 通过 mock API 调用 `getAvailableTables({ table_type: "duya" })`。
2. 选取返回的第一张独牙桌台。
3. 调用 `createReservation` 创建预约。
4. 使用新预约 ID 调用 `getReservationDetail`。
5. 调用 `getMyReservations` 检查列表。
6. 调用 `submitArrival` 提交到店。

实际结果：

```json
{
  "duyaCount": 8,
  "createdId": "R1781970172074",
  "detailId": "reservation_demo_001",
  "createdInDetail": false,
  "createdInMyReservations": false,
  "arrivalStatus": "pending_verify",
  "ok": false
}
```

预期结果：

- `getReservationDetail(createdId)` 应返回新创建预约。
- `getMyReservations` 应包含新创建预约。
- `submitArrival(createdId)` 后，详情或列表刷新应能看到该预约进入 `pending_verify`。

根因旁证：

- `miniprogram/services/api.js` 中 `createReservation` 当前只返回 `{ id, status, ...payload }`，没有写回 `mock.reservations`。
- `getReservationDetail` 查不到 ID 时回退 `mock.reservations[0]`。
- `getMyReservations` 只读取静态 `mock.reservations`。
- `submitArrival` 只返回状态，不更新 mock 列表或详情。

建议回派：

- 前端工程师 Agent 修复 `miniprogram/services/api.js` / `miniprogram/utils/mock.js` 的本地 mock 状态，使 `createReservation/getReservationDetail/getMyReservations/submitArrival` 可形成最小状态闭环。
- 修复后 QA 复跑 mock 链路，再决定是否进入微信开发者工具页面点击。
