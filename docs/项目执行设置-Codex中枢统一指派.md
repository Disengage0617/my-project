# 项目执行设置：Codex 中枢统一指派

## 1. 总原则

本项目默认由 Codex 中枢 agent 统一指派、推进、合并、测试和验收。

除非遇到必须用户参与的事项，否则各 agent 不得在中间节点停下来等待用户指令。当前流程必须从第一步连续执行到验收官完整检核，确认无阻塞问题、无关键缺陷、无未回归风险后，才交给用户检查。

## 2. 固定执行顺序

每个完整流程按以下顺序推进：

1. Codex 中枢：拆解目标、划定边界、分配 agent 和文件范围。
2. 产品经理 Agent：核对需求、流程、页面范围、验收标准。
3. 设计师 Agent：完成信息架构、页面布局、视觉规范、交互状态。
4. 前端工程师 Agent：实现页面、交互、状态刷新、接口接入、错误提示。
5. 后端工程师 Agent：实现接口、云函数、数据读写、权限、校验、状态机。
6. 测试工程师 Agent：跑自动化测试、手工验收清单、边界场景、回归验证。
7. 验收官 Agent：对照 PRD 和验收标准做完整检核，判断是否可交付。
8. Codex 中枢：合并结论，只有验收官确认无关键问题后才找用户检查。

## 2.1 跨 Agent 消息格式

Codex 中枢向任一 agent 分派任务、接收状态、交接、评审或修复指令时，必须使用以下固定格式：

```text
message_type: instruction / status / handoff / review / fix
request_id: REQ-YYYYMMDD-HHMMSS-简短任务名
from_lane: coordinator / product-planning / research / visual-design / frontend / backend / qa / reviewer / simple-helper
to_lane: 目标 lane
created_at: ISO 时间或当前日期时间
recorded_in: 当前对话 / docs/worklog.md / docs/shared.md / lanes/<lane>/worklog.md

消息内容：
- 背景：
- 任务：
- 输入材料：
- 允许改动范围：
- 禁止改动范围：
- 输出要求：
- 验证方式：
- 暂停条件：
```

执行要求：

- 中枢指派、agent 交接、测试反馈、验收官评审、修复任务，都必须套用该格式。
- 如果输出没有使用该格式，视为流程不合规，必须立即重写。
- 阶段结果需要归档时，优先写入 `docs/worklog.md`、`docs/shared.md` 或对应 `lanes/<lane>/worklog.md`。

## 3. 不允许中途停止的情况

以下问题由 Codex 中枢继续指派修复，不需要问用户：

- 代码报错、语法错误、测试失败。
- 页面乱码、布局错位、按钮不可点、状态不刷新。
- 字段映射不一致、接口入参/出参小范围不一致。
- 文档、接口、页面、测试之间的小范围矛盾。
- 缺少加载中、空状态、失败提示、重复提交保护。
- 普通回归缺陷、普通 UI 细节、普通交互问题。
- 当前流程内需要补测试、补入口、补状态、补错误提示。

## 4. 必须暂停找用户的情况

只有以下情况可以暂停并找用户：

- 需要真实外部信息：云环境 ID、账号、密钥、真实门店资料、真实价格、真实桌台编号、真实助教资料。
- 需要真实外部授权：微信开发者工具操作、部署、上传、提交审核、推送代码、覆盖线上配置。
- 需要高风险操作：删除数据、重置数据库、覆盖线上数据、迁移生产数据。
- 业务规则冲突：多个方案会影响范围、成本、上线节奏或门店运营规则。
- 任务边界明显扩大：继续做会混淆项目层级，需要建议新开对话框。

## 5. 验收官检核标准

验收官 Agent 必须完成以下检查后，Codex 中枢才可以把结果交给用户：

- PRD 范围是否覆盖。
- 页面是否无明显乱码、错位、空白和不可读文案。
- 关键用户流程是否跑通。
- 员工/店长流程是否跑通。
- 后端权限、状态机、冲突校验、数据隔离是否通过测试。
- 自动化测试是否通过。
- 失败态、空态、加载态、重复提交保护是否存在。
- 已知缺陷是否修复并回归。
- 剩余问题是否全部标为非阻塞，且有明确后续计划。

## 6. 阶段汇报规则

阶段完成时，Codex 中枢只输出关键结果：

- 本轮执行 agent。
- 本轮完成内容。
- 验证结果。
- 剩余问题或卡点。
- 下一步任务。
- 下一步负责 agent。
- 是否需要新开对话框。

不在每个细小动作后询问“是否继续”。

## 7. 当前项目状态约束

本项目最终目标尚未达成前，不讨论上传、提交审核或发布。

只有在完整产品流程实现、测试工程师回归通过、验收官完整检核无关键问题后，才进入用户检查阶段。
