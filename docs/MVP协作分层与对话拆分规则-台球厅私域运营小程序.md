# MVP协作分层与对话拆分规则：台球厅私域运营小程序

## 1. 固定协作角色

| agent | 主责 | 典型产物 |
|---|---|---|
| Codex 中枢 | 拆解、分派、合并、验收 | 回合结果、任务边界、风险清单 |
| 产品经理 agent | 规则、流程、验收标准 | PRD、状态机、验收用例 |
| 设计师 agent | 信息架构、低保真、交互状态 | 页面结构、关键状态、空状态 |
| 后端工程师 agent | 云函数、数据库、权限、校验 | 数据模型、接口、种子脚本、规则测试 |
| 前端工程师 agent | 小程序页面、表单、接口接入 | 页面实现、状态刷新、错误提示 |
| QA agent | 测试用例、缺陷复核 | 测试清单、缺陷分级、回归结果 |
| 验收官 agent | 发布前覆盖检查 | 验收结论、剩余风险 |

## 2. 当前项目分层

| 层级 | 目录 | 说明 |
|---|---|---|
| 产品层 | `docs/product`、根目录业务文档 | 已确认规则、MVP 范围、里程碑 |
| 后端层 | `cloudfunctions/api`、`docs/backend` | 云函数、数据库规则、接口协议 |
| 前端层 | `miniprogram`、`docs/frontend` | 小程序页面、路由、组件和 mock |
| 测试层 | `cloudfunctions/api/test`、`docs/testing` | 自动化测试、验收用例 |
| 协作层 | `docs/MVP协作分层与对话拆分规则-台球厅私域运营小程序.md` | agent 分工和新对话判断 |

## 3. 什么时候不需要新对话

- 单轮改动在同一层内，例如只改云函数接口、只改某几个小程序页面。
- 当前任务能在 1-2 个 agent 内完成。
- 不需要长期保留独立上下文。
- 不涉及大规模 UI 重构、数据库迁移或上线验收。

## 4. 什么时候建议新开对话

- 后端、前端、设计、测试要长期并行推进，且每条线都有连续多轮任务。
- 要做完整 UI 视觉设计或单独设计系统。
- 要做数据库迁移、云开发环境部署、线上发布检查。
- 要让 QA 长期维护缺陷清单和回归记录。
- 当前对话上下文过长，影响后续精准执行。

## 5. 建议的新对话分层

| 对话框 | 负责人 | 用途 | 当前是否需要 |
|---|---|---|---|
| 主控对话 | Codex 中枢 | 总控、决策、合并、验收 | 需要，当前对话继续作为主控 |
| 后端对话 | 后端工程师 agent | 数据库、云函数、联调、测试 | 暂不需要；下一阶段若进入部署联调可新开 |
| 前端对话 | 前端工程师 agent | 页面表单、接口接入、交互修复 | 暂不需要；等接口稳定后可新开 |
| 设计对话 | 设计师 agent | 视觉规范、低保真到高保真 | 暂不需要；如果要精细 UI 可新开 |
| QA 对话 | QA agent | 测试用例、缺陷跟踪、回归 | 暂不需要；上线前建议新开 |

## 6. 每轮输出固定格式

每轮完成后输出：

- 本轮执行 agent。
- 本轮完成结果。
- 验证结果。
- 下一轮任务。
- 下一轮负责 agent。
- 是否建议新开对话框。
