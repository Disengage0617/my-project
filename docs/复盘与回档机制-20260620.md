# 复盘与回档机制 - 2026-06-20

## 目标

避免同一个用户可见问题被多轮“本地通过”误判为已修复。后续遇到重复失败，先收敛证据、建立回档点，再决定修复动作。

## 当前复盘：预约页独牙筛选仍为 0 张

- 用户可见现象：微信开发者工具预约页选择“独牙”仍显示 0 张。
- 已经做过的层级：本地 mock、本地后端测试、云函数部署包入口修复、部署包 smoke。
- 当前不能关闭的问题：用户业务页面仍失败，所以不得写成“已修复”或“验收通过”。
- 最可能遗漏层级：真实云数据库 `billiard_table` 数据、真实云函数 action 返回体、调用环境/缓存、前端运行时实际 payload 和响应。

## 已犯错误

1. 把本地自动化测试通过当成真实页面通过。
2. 把云函数包结构 smoke 通过当成真实 `getAvailableTables` action 通过。
3. 在用户已经截图证明失败后，仍多次沿着代码层继续补丁，缺少运行时数据源闭环。
4. QA/验收官报告没有把“用户截图失败优先级最高”作为阻塞项坚持到底。

## 后续禁止项

- 不得用 mock、本地单测、静态扫描、部署包 smoke 替代用户业务页面或真实云端返回。
- 同一缺陷连续两轮失败后，不得继续新增业务代码；必须进入 `stop_coding_diagnose`。
- 未建立回档点前，不得写真实数据库、迁移数据、覆盖线上配置。
- 未拿到用户明确授权前，不得执行数据初始化、删除、重置或生产配置覆盖。

## 回档点要求

### 云函数

- 部署前必须下载当前云函数源码到 `.tmp_cloud_download_*`。
- 记录云函数名、环境 ID、部署时间、包体大小、入口文件结构。
- 部署后若用户页面仍失败或出现更大范围错误，优先使用部署前下载包或云开发控制台版本恢复。

### 数据库

- 写库前必须记录集合名、`store_id`、目标记录 ID、before 摘要和预期 after。
- 只允许写测试门店或用户明确指定的测试资源。
- 数据层不做自动回滚；需要恢复时必须再次获得用户授权。

### 前端

- 修改前记录相关页面文件和接口调用路径。
- 如果真实页面验证失败，先抓实际 payload/response，再决定是否回退前端逻辑。

## 当前下一步

1. 后端工程师 Agent 做只读诊断：确认真实 `getAvailableTables` 返回体和真实 `billiard_table` 是否存在 C01-C08、`table_type=duya`、`enabled=true`、可用状态。
2. 如果真实库缺 C01-C08：中枢向用户申请单独写库授权，并要求后端先给 before/after 与回档方案。
3. 如果真实库有 C01-C08：转前端工程师 Agent 核对真实 payload/response 与页面过滤逻辑。
4. 任一阶段都不得写“已修复”，直到用户业务页面显示独牙桌台或有效截图/返回体证明通过。

## Handoff 约束

后续所有独牙问题相关 agent 回传必须包含：

- 当前验证层级：本地代码 / mock / 云函数包 / 真实 action / 真实 DB / 微信开发者工具页面 / 真机。
- 证据：命令、返回体摘要、截图或用户手动复核结果。
- 是否建立回档点。
- 下一步最小动作。
- 是否需要用户授权。
