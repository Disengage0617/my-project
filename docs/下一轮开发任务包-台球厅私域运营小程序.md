# 下一轮开发任务包：台球厅私域运营小程序

## 1. 当前协作状态

当前仍按多 agent 协作推进，Codex 负责中枢整合。

下一棒建议顺序：
1. 产品经理：补齐详细 PRD、状态机、业务规则。
2. 后端工程师：先做数据表、接口协议、预约冲突和未到限制逻辑。
3. 设计师：同步做低保真原型和关键状态页面。
4. 前端工程师：等接口草案和原型稳定后搭小程序页面骨架。
5. 测试工程师：根据状态机和验收标准写测试用例。

优先启动：产品经理和后端工程师。原因是预约规则、状态机、未到限制、助教预约、活动报名会决定数据结构和页面状态。

## 2. 产品经理任务

### 2.1 业务规则补齐

已确认：
- 24 小时营业。
- 40 张桌。
- 桌型按价格由低到高：普台、乔氏银腿、独牙、乔氏金腿、乔氏玫瑰金。
- 不收定金。
- 小程序内商家后台。
- 不做桌台二维码。
- 用户提交到店，员工核实确认。
- 用户可提前 30 分钟预约。
- 未到店禁止预约 3 天。
- 员工可更改客户是否到店状态。
- 助教支持单独预约。
- 活动由商家上传，用户展示和报名。
- 活动报名需授权微信昵称和手机号。

待补齐：
- 桌台预约最短时长、最长时长。
- 预约迟到多久释放桌台。
- 用户是否允许主动取消预约。
- 助教计费单位和服务时长。
- 活动报名默认是否审核。
- 未到店后是否允许申诉。
- 40 张桌真实编号和区域命名。

### 2.2 状态机

桌台预约状态：
- 待确认
- 待到店
- 待核实
- 已到店
- 进行中
- 已完成
- 已取消
- 未到店
- 已释放

用户点击“我已到店”：
- 待到店 -> 待核实

员工确认到店：
- 待核实 -> 已到店

员工开台：
- 已到店 -> 进行中
- 桌台状态 -> 使用中

员工关台：
- 进行中 -> 已完成
- 桌台状态 -> 空闲或清洁中

员工标记未到：
- 待到店/待核实 -> 未到店
- 释放桌台
- 写入 3 天预约限制

### 3.3 核心规则

预约时间：
- `start_time >= now + 30分钟`

桌台冲突：
- 同桌台存在 `start < existing_end AND end > existing_start` 即冲突。

助教冲突：
- 同助教存在 `start < existing_end AND end > existing_start` 即冲突。

未到限制：
- 创建预约前查 `no_show_record`。
- 当前时间在限制期内，拒绝预约。
- 员工标记未到后，限制结束时间为当前时间 + 3 天。
- 店长可解除，必须记录解除人和原因。

活动报名：
- 报名前必须授权微信昵称和手机号。
- 有名额时需要锁库存，避免超报。
- 需审核活动进入待审核，不需审核活动直接报名成功。

## 6. 测试工程师任务

P0 测试用例：
- 用户提前 30 分钟以内预约被拒绝。
- 用户提前 30 分钟以外预约成功。
- 同桌同时间重复预约被拒绝。
- 用户提交到店后，员工端出现待核实。
- 员工确认到店后可开台。
- 员工标记未到后，用户 3 天内不可预约。
- 店长解除限制后，用户可预约。
- 助教同时间重复预约被拒绝。
- 活动报名未授权手机号被拒绝。
- 活动满额后不可继续报名。
- 普通员工不可导出客户手机号。
