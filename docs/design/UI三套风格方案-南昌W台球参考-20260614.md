## 方向锁定

## 设计读取

Reading this as: 台球俱乐部门店预约小程序，面向手机端用户快速看空桌、预约、到店、员工核实；视觉语言锁定为“夜场台球俱乐部 / 深色会所 / 霓虹灯带 / 桌台中心感”，但产品定位仍是工具型小程序，不做营销落地页。

Dark Neon Club 的关键不是铺满霓虹，而是用深色空间、台呢绿、冷蓝线性灯、少量暖橙警示，把“球房氛围”翻译成清晰的信息层级。

## 设计原则

- 深色为底，但所有正文必须保证可读，不允许灰字压黑底。
- 霓虹只用于边线、状态、重点数字，不做大面积廉价渐变。
- 首页和预约页优先服务“看空桌、选桌、提交预约”。
- 员工工作台优先服务“待核实、开台、关台”，不能为了酷牺牲效率。
- 卡片数量要少，层级要清楚，禁止泛卡片堆叠。
- 任何核心页面都必须有 loading、empty、error 的可识别状态。

### 使用比例

- 深色背景：70%。
- 深色卡片：20%。
- 台呢绿主操作：6%。
- 冷蓝灯带：3%。
- 暖橙 / 危险色：1%，只用于异常和强提醒。

## 卡片规范

### 基础卡片

- 背景：`--dn-surface`。
- 边框：`1rpx solid var(--dn-line-soft)`。
- 圆角：`20rpx`。
- 内边距：`24rpx`。
- 阴影：`0 20rpx 44rpx var(--dn-shadow)`。
- 卡片之间间距：`18rpx` 到 `24rpx`。

### 霓虹重点卡片

- 用于首页 hero、工作台待核实、选中桌台。
- 边框：`1rpx solid var(--dn-line)`。
- 可加一条 `2rpx` 冷蓝顶边或左边，不使用整圈强发光。
- 背景可用 `linear-gradient(135deg, #101a18, #142721)`，不得出现紫蓝大渐变。

### 桌台卡片

- 桌台编号最大，放左上。
- 状态 tag 放右上。
- 区域 / 类型放第二行。
- 价格放底部，颜色用 `--dn-gold`。
- 选中态：台呢绿边框 + 浅绿内发光 + 右下角小圆点。

## 六个核心页面布局重构建议

### 1. 首页

目标：3 秒内知道门店、空桌、助教、预约入口。

布局：

```text
深色沉浸 Hero
- 今日可约 / 营业中
- 门店名
- 营业时间 · 桌台数 · 到店核实
- 空桌 / 空闲助教 两个 metric tile
- 暖金色立即预约按钮

快捷入口
- 分区时段价
- 陪练服务

门店活动
- 活动名
- 名额
- 状态

预约规则
- 提前预约
- 爽约限制
- 到店核实
```

视觉要求：

- Hero 深色，指标卡用半透明深色，不用白卡。
- 立即预约按钮必须比其他入口更显眼。
- 活动列表最多显示 2 条，超过进入活动列表页。

### 2. 预约页

目标：快速完成条件选择、桌台选择、助教选择、提交。

布局：

```text
深色页头
- 桌台预约
- 选好时段，到店即开

预约条件霓虹面板
- 开始时间 · 时长 · 人数
- 时长步进器
- 人数步进器

选择桌台
- 两列桌台卡
- 编号 / 状态 / 区域类型 / 价格
- 选中态强提示

助教需求
- 单列助教卡
- 姓名 / 标签 / 价格 / 状态

规则确认
- 到店核实

底部固定提交
- 提交预约
```

视觉要求：

- 桌台卡比助教卡更重要。
- 价格用暖金色。
- 禁止把所有桌台做成同权重白卡。

### 3. 我的预约

目标：用户知道下一步要不要到店、是否可提交到店。

布局：

```text
深色页头
- 我的预约
- 到店前后都看得清

状态分组
- 待到店
- 使用中
- 已完成

预约卡
- 桌台编号 · 类型
- 时间 / 助教
- 当前状态 tag
- 主操作：我已到店
```

视觉要求：

- 待到店卡片使用冷蓝边线。
- “我已到店”只在待到店状态强显示。
- 已完成记录降低亮度，避免抢焦点。

### 4. 工作台

目标：员工优先处理待核实，再看桌台网格。

布局：

```text
深色页头
- 员工工作台
- 今天的预约和开台

待核实重点卡
- 大数字
- 进入核实按钮

桌台网格入口
- 空闲 / 预约 / 使用中 / 维护

今日预约分组
- 待核实
- 使用中
- 今日全部
```

视觉要求：

- 待核实数字必须最大。
- 开台、关台、标记未到按钮颜色必须区分。
- 员工端不能过度霓虹，优先高对比。

### 5. 活动报名

目标：确认用户信息、手机号、人数并提交。

布局：

```text
深色页头
- 活动报名
- 确认参与信息

用户信息面板
- 微信昵称
- 手机号
- 输入 / 授权手机号

参与人数
- 步进器

报名规则

底部提交
```

视觉要求：

- 输入框背景用深色二级面，不用纯黑。
- 授权手机号是次按钮，提交报名是主按钮。
- 错误信息使用红色状态条，不弹一堆 toast。

### 6. 预约详情

目标：看清当前状态和下一步。

布局：

```text
深色页头
- 预约详情
- 状态和到店规则

预约摘要重点卡
- 桌台编号 · 类型
- 时间
- 当前状态
- 助教

状态时间线
- 已预约
- 待到店
- 待核实
- 使用中
- 已完成

到店说明
- 我已到店
- 员工核实
```

视觉要求：

- 当前节点用台呢绿发光点。
- 未到节点用低亮灰。
- 失败 / 爽约节点用红色，不混用橙色。

## QA 视觉验收标准

- 首页、预约、我的预约、工作台、活动报名、预约详情必须全部进入微信开发者工具截图。
- 不得出现裸文本、无背景文本堆叠、按钮像普通文本。
- 深色背景下正文对比度必须可读，不能使用低亮灰作为正文。
- 霓虹元素只允许作为边线、状态点、重点数字，不允许满屏发光。
- 主按钮必须一眼可见，且所有按钮文字不换行。
- 桌台选中态必须明显区别于未选中。
- 错误、空、加载状态必须出现在独立面板中。
- 工作台待核实数量必须比普通预约列表更突出。
- 预约详情当前状态必须在状态流转中明确高亮。
- 不允许廉价紫蓝渐变、随机色彩、泛卡片无层级堆叠。

## 暂停条件

以下信息会影响品牌最终视觉，但不阻塞前端先按 Dark Neon Club 执行：

- 真实 W 台球 logo。
- 真实门店照片。
- 真实装修图。
- 指定灯带色或品牌主色。
- 真实价格、活动素材。

若用户提供以上素材，设计师 Agent 需要二次校准色彩和首页品牌区。

## 当前结论

Dark Neon Club 可以作为最终视觉方向执行，但必须按“深色工具 UI”处理，而不是夜店营销页。前端应先完成全局深色 token 和六个核心页面结构调整，QA 再做真实截图视觉冒烟。
